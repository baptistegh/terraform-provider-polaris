# AGENTS.md

Guidance for coding agents (and humans) working in this repository.

## Project

Terraform provider for [Apache Polaris](https://polaris.apache.org/), the open-source implementation of the Iceberg REST Catalog specification. Allows managing Polaris catalogs, namespaces, principals, roles, and grants via Terraform.

## Commands

```bash
# Build
go build ./...

# Start / stop a local Polaris (Docker, bootstrap credentials root / s3cr3t, realm POLARIS)
make dev-up
make dev-down

# Run unit tests (CI runs this in the Build job). Acceptance tests (TestAcc*)
# skip themselves without TF_ACC=1, so this needs no Polaris instance.
make test

# Run the acceptance tests against the local Polaris
make testacc

# Run a single acceptance test
TF_ACC=1 POLARIS_BASE_URL=http://localhost:8181 POLARIS_CLIENT_ID=root POLARIS_CLIENT_SECRET=s3cr3t POLARIS_REALM=POLARIS \
  go test ./internal/provider/ -run TestAccResourcePrincipal_basic -v

# Lint (runs golangci-lint in Docker, version pinned in Makefile)
make lint

# Re-generate the management API client (after updating spec/) — runs openapi-generator in Docker
make generate-client

# Generate Terraform provider docs
make docs

# Both of the above (what CI checks)
make generate

# Format
gofmt -s -w .

# Install provider locally for manual testing
go install .
```

## Architecture

This is a [Terraform Plugin Framework](https://developer.hashicorp.com/terraform/plugin/framework) provider (not the legacy SDK). All resources and data sources use the `framework` package patterns (`resource.Resource`, `datasource.DataSource`).

### Directory layout

```
main.go                        # calls providerserver.Serve
spec/
  polaris-management-service.yml  # upstream OpenAPI spec (source of truth — do not edit)
pkg/
  polarismanagement/           # generated Go client for /api/management/v1 (importable externally)
    openapi-generator.yaml     # openapi-generator config (the only hand-written file here)
    *.go                       # generated — do not edit by hand (`make generate-client` wipes and rewrites them)
internal/
  provider/
    provider.go                # provider.Provider implementation, ProviderData, token fetching; registers resources/data sources
    apiclient.go               # newManagementClient, checkResponse, isNotFound, doJSON, isNotFoundError
    grants.go                  # shared grant helpers (list/add/revoke via doJSON)
    catalog.go                 # catalog payloads and API calls via doJSON, model conversions (shared by resource and data source)
    resource_catalog.go        # polaris_catalog
    resource_principal.go      # polaris_principal
    resource_principal_role.go # polaris_principal_role
    resource_catalog_role.go   # polaris_catalog_role
    resource_principal_role_assignment.go
    resource_catalog_role_assignment.go
    resource_catalog_grant.go
    resource_namespace_grant.go
    resource_table_grant.go
    resource_view_grant.go
    resource_policy_grant.go
    resource_semantic_model_grant.go
    datasource_realm.go        # polaris_realm (no API call, reads provider config)
    datasource_principal.go    # polaris_principal
    datasource_principals.go   # polaris_principals (and _principal_role(s), _catalog(s), _catalog_role(s) data sources)
    roles.go                   # read-only role/principal attributes and conversions shared by those data sources
    schemaconv.go              # computedAttributes: derives a read-only data source schema from a resource schema
    provider_test.go           # providerFactories, testAccPreCheck, testAccProviderConfig, testCreate* helpers
examples/
  provider/provider.tf
  resources/<type>/            # also contains examples for planned, not yet implemented types
  data-sources/<type>/
docs/                          # generated by tfplugindocs (`make docs`)
```

### Generated client (`pkg/polarismanagement`)

Generated from `spec/polaris-management-service.yml` with [OpenAPI Generator](https://openapi-generator.tech) (`go` generator), run through the `openapitools/openapi-generator-cli` Docker image. The image version is pinned by `OPENAPI_GENERATOR_VERSION` in the `Makefile` (tracked by Renovate). The spec covers the full `/api/management/v1` surface: catalogs, principals, principal roles, catalog roles, and grants.

Inside the provider, build the client with `newManagementClient` (`internal/provider/apiclient.go`), which sets the base URL, HTTP client, `Authorization: Bearer <token>` and realm headers on the generated `Configuration`. Calls use the request-builder style and must be checked with `checkResponse`, because the generated client returns an error for every non-2xx status:

```go
role, httpResp, err := client.DefaultAPI.GetCatalogRole(ctx, catalog, name).Execute()
if isNotFound(httpResp) { /* gone */ }
if err := checkResponse(httpResp, err, http.StatusOK); err != nil { /* report */ }
```

Grants and catalogs are the exceptions: the generator flattens `allOf` + discriminator subtypes, so the generated `GrantResource` only carries `type`, `StorageConfigInfo` drops every S3/Azure/GCS field and `Catalog` has no `connectionConfigInfo`. Those endpoints go through `doJSON` with hand-written payloads (`internal/provider/grants.go`, `internal/provider/catalog.go`); use `isNotFoundError(err)` to detect a 404 from `doJSON`.

Authentication uses OAuth2 client credentials against `/api/catalog/v1/oauth/tokens`, which the management spec does not cover; `fetchToken` in `provider.go` implements it (scope `PRINCIPAL_ROLE:ALL`). A pre-fetched `token` can be configured instead.

### Provider configuration

```hcl
provider "polaris" {
  base_url      = "http://localhost:8181" # or POLARIS_BASE_URL
  client_id     = "root"                  # or POLARIS_CLIENT_ID
  client_secret = "..."                   # or POLARIS_CLIENT_SECRET
  realm         = "POLARIS"               # optional, or POLARIS_REALM
}
```

Alternatively set `token` (or `POLARIS_TOKEN`) instead of `client_id`/`client_secret`. `realm_header` (default `Polaris-Realm`) and `tls_insecure_skip_verify` are also available.

### File naming — MUST follow this convention

| Kind | Source file | Test file |
|---|---|---|
| Resource | `resource_<type>.go` | `resource_<type>_test.go` |
| Data source | `datasource_<type>.go` | `datasource_<type>_test.go` |
| Ephemeral resource | `ephemeral_<type>.go` | `ephemeral_<type>_test.go` |

Where `<type>` is the Terraform type name without the `polaris_` prefix, with slashes replaced by underscores. Examples: `resource_catalog.go`, `datasource_realm.go`, `ephemeral_principal_credentials.go`.

### Key conventions

- Each resource file defines a struct implementing `resource.Resource` (and optionally `resource.ResourceWithImportState`).
- State models are separate structs with `tfsdk` tags.
- `provider.Configure()` passes `*ProviderData` (defined in `provider.go`) as both `resp.ResourceData` and `resp.DataSourceData`. Every resource and data source must type-assert to `*ProviderData` in their own `Configure` method.
- Acceptance tests use `resource.Test` with `providerFactories` and helpers from `provider_test.go`. Test environment variables: `TF_ACC=1`, `POLARIS_BASE_URL`, `POLARIS_CLIENT_ID`, `POLARIS_CLIENT_SECRET`, `POLARIS_REALM`.
- Tests that need a catalog call `testCreateCatalog(t)` — it creates a random catalog via the API and registers `t.Cleanup` to delete it. No `POLARIS_TEST_CATALOG` env var is needed.
- Tests that need a namespace, table, view or semantic model call `testCreateNamespace`, `testCreateTable`, `testCreateView` or `testCreateSemanticModel` — same pattern.
- `docker-compose.yml` (used locally and in CI) enables the `ENABLE_CATALOG_FEDERATION` and `ENABLE_SEMANTIC_MODELS` server features that the federated catalog and semantic model grant tests need.

### Testing — MANDATORY

**Always write or update an acceptance test file whenever you add or modify a resource, data source, or ephemeral resource.** No exceptions.

- Test file lives alongside the source file: `datasource_principal_test.go` next to `datasource_principal.go`.
- Every public behaviour must be covered: the happy path, every optional/computed attribute that has non-trivial logic, and any default-value behaviour.
- Use `checkTFAcc(t)` and `testAccPreCheck(t)` at the top of every `TestAcc*` function.
- Use `testAccProviderConfig()` for the provider block — never hardcode credentials.
- Test functions are named `TestAcc<Kind><Type>_<scenario>`, e.g. `TestAccDatasourcePrincipal_defaultsToProviderClientID`.
- Logic that does not need a Polaris server (helpers in `apiclient.go`, `grants.go`, provider config validation, ...) should get plain unit tests (`Test<Name>`, no `checkTFAcc`), using `httptest` for HTTP behaviour. They run in CI via `make test`.

### Commits and AI attribution — MANDATORY

An AI agent is **NEVER** a co-author. Never add a `Co-Authored-By:` trailer (or any other authorship credit) for an AI agent: the human who commits is the author and is responsible for the change.

Instead, every commit an AI agent contributed to **must** end with exactly one of these Git trailers, depending on what the agent did:

| Trailer | Use when |
|---|---|
| `Generated-By:` | The agent wrote the change (code, tests, docs, config), even if a human then reviewed or adjusted it. |
| `Assisted-By:` | A human wrote the change and the agent only helped: suggestions, review, debugging, research, explanations. |

Format: `<Trailer>: <agent> (<model>)`, as the last paragraph of the commit message, for example:

```
docs: simplify README

Drop the resource tables, which duplicate the Registry docs.

Generated-By: Claude Code (claude-opus-5-5)
```

The same rule applies to pull request descriptions: no co-author credit for an agent; say whether it generated or assisted.
